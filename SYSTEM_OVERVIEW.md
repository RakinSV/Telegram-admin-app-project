## 1. Что это в двух словах

Система, которая **сама ведёт Telegram-каналы за владельца**: читает чужие
каналы-источники, переписывает их посты в уникальный профессиональный текст
через ИИ, генерирует обложки, показывает владельцу на модерацию (или постит
сама по расписанию) и публикует в его собственные каналы/группы. Плюс —
**Guardian**, отдельный бот-модератор, который защищает эти группы от спама,
рейдов и мусора.

Плюс **Engage** — третий бот, который превращает читателей в участников:
викторины по опубликованным постам, рефералы с антинакруткой, конкурсы с
проверяемым розыгрышем.

Это уже не скрипт, а полноценный продукт: **~24 600 строк Python, 1266 тестов,
двуязычная веб-админка (RU/EN), три Telegram-бота, 28 миграций БД.**

## 2. Стек и архитектура

- **Python 3.11+**, всё асинхронное (asyncio).
- **Чтение источников** — Telethon (юзер-сессия): читает любые публичные
  каналы без ограничений Bot API.
- **Публикация и модерация** — Telegram Bot API (python-telegram-bot).
- **Рерайт/эмбеддинги/картинки** — любой **OpenAI-совместимый** провайдер
  (`base_url` + `api_key` в настройках): сам OpenAI, OpenRouter, локальная
  Ollama, шлюз OmniRoute и т.д. Провайдер меняется в админке, не в коде.
- **БД** — SQLite (один файл, легко бэкапить), миграции через Alembic с
  первого дня — переезд на Postgres безболезненный.
- **Планировщик** — APScheduler внутри процесса (без Celery/Redis).
- **Веб-админка** — FastAPI + Jinja2, сервер-сайд рендеринг.
- **Деплой** — Docker Compose; тестовый стенд на 168.168.88.112.

### Путь поста (жизненный цикл)

```
Источники (N каналов + RSS-ленты)
      │  Telethon listener / RSS-поллер
      ▼
Фильтрация (стоп-слова / обязательные слова)  →  отсев (filtered_out)
      │
Дедупликация (хэш + семантическая по эмбеддингам)  →  отсев дублей
      ▼
Очередь постов (SQLite, статус-машина:
   new → rewriting → rewritten → approved/rejected → posted / failed)
      │
Переход по ссылке в посте (trafilatura: тянет ПОЛНУЮ статью, не тизер)
      ▼
РЕРАЙТ:
   • обычный (1 вызов LLM) ИЛИ
   • «Редакция из двух агентов» (журналист → редактор-фактчекер → правка)
      │  + N вариантов текста, + добор источников, + языки целей
      ▼
Обложка (картинка статьи / AI-генерация / Unsplash / ComfyUI)
      ▼
Модерация:
   • ручная — бот шлёт пост владельцу с кнопками ✅❌✏️ + веб-админка
   • авто — по расписанию/слотам без модерации
      ▼
Публикация в одну/несколько целевых групп (параллельно, с учётом языка цели)
      ▼
Статистика (просмотры, реакции, форварды), growth-трекер, дайджесты
```

## 3. Функционал репост-системы (по блокам)

### Захват контента
- **F01 Источники** — список каналов, у каждого свой стиль-профиль рерайта и
  маршрутизация в конкретные цели. Массовое добавление через textarea.
- **F02 Telethon listener** — слушает новые посты в реальном времени.
- **RSS-ленты как источник** — помимо Telegram-каналов, опрос RSS.
- **Обнаруженные чаты** — когда бота добавляют в чат, он сам появляется в
  списке возможных целей (с проверкой прав на постинг).

### Фильтрация и дедупликация
- **F03 Фильтрация по словам** — стоп-слова (отсекают) и обязательные слова.
- **F04 Дедуп по хэшу** + **F13 Семантический дубль-чек** — эмбеддинги +
  косинусное сходство ловят перефразированные дубли из разных каналов за
  окно в N дней. Приём поста общий для Telegram и RSS
  (`tg_repost/ingest.py`) — раньше логика была скопирована, и RSS-копия
  дедуп не делала вовсе.
- **F51 Сюжеты** — повтор из НЕЗАВИСИМОГО источника не выбрасывается, а
  цепляется к первому посту в кластер и уходит в фактчек как подтверждение.
  Публикуется по-прежнему один пост. Буквальный копипаст в сюжет не идёт.

### Рерайт — сердце системы
- **F06 Рерайт** через OpenAI-совместимое API, промпты в файлах и правятся в
  админке без передеплоя.
- **F15 Стиль-профили** — 5 голосов (default/новость/мнение/инструкция/юмор),
  выбираются на источнике, промпт каждого редактируется в админке.
- **F16 Переход по ссылке** — trafilatura вытаскивает тело статьи (без
  меню/футера/рекламы), рерайт идёт по ПОЛНОМУ тексту, а не по анонсу.
- **Анти-галлюцинация** — если реального материала мало (голый заголовок без
  статьи), пост не пускается к модели вообще (иначе ИИ выдумывает факты).
- **N вариантов текста на пост** — владелец выбирает лучший кнопками ◀▶ в
  боте или в веб-галерее.
- **Языки целей** — один источник кормит и русские, и англоязычные каналы;
  пост переписывается на язык КАЖДОЙ целевой группы.
- **Анти-ИИ блок** — правила «пиши не как нейросеть», приклеиваются ко всем
  стилям.

### 🔥 F40 — Редакция из двух агентов (главная фича, 2026-08-01)
Вместо «модель написала начисто» — редакционный конвейер:
1. **Журналист** (персона: 20 лет опыта) пишет черновик.
2. **Редактор-фактчекер** сверяет черновик с источниками, пишет
   пронумерованные замечания, вердикт OK/ПРАВИТЬ, помечает спорные факты.
3. **Веб-сверка** помеченных фактов через поиск (SearXNG/Brave) — находки
   идут журналисту.
4. **Журналист переписывает** по замечаниям и находкам. Цикл — до вердикта
   OK или до лимита раундов.

Замечания редактора **сохраняются и показываются при модерации**. По умолчанию
ВКЛ, 1 раунд. Дороже: 1 раунд = 3 вызова LLM на вариант, поэтому под
выключателем. Ошибка баланса (402) на любом шаге останавливает пачку (посты
остаются `new`), не сжигая очередь.

### Обложки
- **F18 Авто-обложки** — если у поста нет картинки (или включена замена):
  реальная картинка статьи по ссылке / AI-генерация (OpenAI images) / Unsplash
  / локальный ComfyUI. N вариантов обложки, выбор при модерации.

### Модерация и публикация
- **F07 Ручное одобрение** — бот шлёт пост в личку с кнопками: ✅ Одобрить,
  ❌ Отклонить, ✏️ Редактировать, другой текст (◀▶), другая картинка.
- **F11 Авто-постинг по расписанию** + слоты публикации (HH:MM).
- **F12 Несколько целей** — параллельная публикация, у каждой цели свой язык
  и права; частичный успех не роняет весь пост в failed.
- **F19 Умное расписание** — анализ пиков активности аудитории → сдвиг времени.

### Управление уже опубликованным
- **F29** — редактировать/удалять/закреплять опубликованный пост.
- **F31** — сбор реакций и форвардов в статистику.
- **F32** — управление инвайт-ссылками и заявками на вступление.
- **F33 Опросы (polls)** в ленте.
- **F34 Inline-кнопки** на опубликованном посте (в т.ч. кнопка «Источник»).
- **F35 Ручной учёт рекламного дохода**.
- **F38 Экспорт** контента канала (JSON/CSV).

### Лонгриды и рост
- **Статьи на Telegraph** — длинные материалы уходят на Telegraph, в канал
  идёт тизер со ссылкой.
- **F14 Статистика** — просмотры, реакции, форварды по постам.
- **F20 Авто-дайджест** — раз в неделю ИИ собирает топ постов в сводку.
- **F22 Growth-трекер** — корреляция прироста подписчиков с типом контента.
- **F21 Нативная реклама** — каждый N-й пост рекламный, ИИ вписывает блок в
  контекст.

### Антибан и прокси
- **F17 Антибан** — рандомизация задержек, лимиты чтений в час (Telethon
  работает через юзер-сессию, риск блокировки выше, чем у бота).
- **Единый прокси-раздел** — три типа (MTProto / SOCKS5 / HTTP(S)), у каждого
  своя галочка включения и поля адрес/логин/пароль, плюс три галочки
  применения: для Telegram, для нейросети рерайта, для картиночной нейросети.
  Пароли скрыты (кнопка «показать» в один клик), адреса/логины редактируемые.

## 4. Guardian — бот-модератор групп (второй бот)

Отдельный процесс/контейнер, защищает целевые группы. Настраивается **по
каждой защищаемой группе** (не глобально, F28). Функционал G01–G17:

- **CAPTCHA на вход** (математическая / кнопка) с тайм-аутом.
- **Приветствие** новым участникам.
- **Три режима антиспама**: ключевые слова / AI-классификатор (LLM оценивает
  спамность с порогом уверенности) / гибридный (эвристики подозрительности).
- **Фильтры**: стоп-слова (по чату), разрешённые домены (белый список ссылок),
  доверенные пользователи.
- **Система варнов** — эскалация варн → мут → кик → бан, со сбросом по TTL.
- **Анти-флуд** — лимит сообщений в окно.
- **Анти-рейд** — при всплеске вступлений включается защитный режим.
- **Анализ профиля** новых участников + **тихие часы**.
- **Автодоверие** по таймеру (старый участник перестаёт проверяться).
- **Лог-канал** — все действия модерации пишутся в отдельный канал.
- **Статистика** — daily_stats, команды `/stats`, `/growth`, 21 админ-команда.

Guardian управляется и через свои Telegram-команды, и через веб-админку.
Прокси у Guardian **свой отдельный** (`GUARDIAN_BOT_API_PROXY_URL`, только .env).

## 5. Веб-админка (F23)

FastAPI + Jinja2, двуязычная (RU/EN, переключатель в шапке). Ключевое:

- **Единый вход** — бутстрап через setup-токен, вход по паролю, сессии,
  rate-limit на логин.
- **Настройки и секреты на одной странице** `/settings`, сгруппированы по
  ~22 тематическим блокам с якорной навигацией. Список групп:
  telegram, proxy, rewrite, **editorial**, filtering, pipeline, antiban,
  posting_schedule, semantic_dedup, stats, negative_reactions, style_profiles,
  rss, telegraph, enrichment, covers, smart_schedule, digest, ads, growth,
  post_source_button, guardian_bot.
- **Секреты** — хранятся в БД шифрованными (Fernet), write-only, показывают
  только маску; «показать» расшифровывает в один клик (страница уже под
  логином). Секреты живут в БД/админке, **не в .env**.
- **Разделы**: дашборд, источники, цели, модерация (лента + детальная
  карточка с вариантами и замечаниями редактора), статистика/лучшее
  время/рост, реклама, Telethon-сессии, компоненты (старт/рестарт
  listener/бота/планировщика), аудит-лог, логи, Guardian (дашборд + настройки
  + стоп-слова/домены/доверенные).

## 7. Инфраструктура и деплой

- **Тестовый стенд**: `168.168.88.112` (Win10 + Docker Desktop), путь
  `C:/deploy/tg-app`, порт 8001. SSH:
  `ssh -i ~/.ssh/id_ed25519_win112 Root-Adm9@168.168.88.112`.
- **Деплой**: пересобирать **все три сервиса**, а не один:
  `docker compose build tg_repost guardian engage && docker compose up -d --force-recreate tg_repost guardian engage`
  (обычный `up -d --build` иногда не пересоздаёт контейнер).

  **Почему все три.** У `guardian` и `engage` свои образы из того же
  Dockerfile. Пересборка одного `tg_repost` оставляет их на старом коде, и это
  не безобидно: 2026-08-18 Guardian бился в цикле перезапусков с
  «Can't locate revision identified by '0003_spam_reviews'» — миграцию
  применил новый tg_repost, а старый образ Guardian о ней не знал. Со стороны
  это выглядело как сломанный бот, хотя сломан был деплой.
- **Провайдер ИИ**: подключается **OmniRoute** — OpenAI-совместимый шлюз в
  Docker (LXC 304 на server009 / 88.210, дашборд 168.168.88.34:20128).
  Достаточно указать его `base_url` + ключ в `/settings → Рерайт`.
- **Репозиторий**: github.com/RakinSV/Telegram-admin-app-project (main).

## 9. Что НЕ сделано / бэклог

Осознанно отложено, а не «руки не дошли» — у каждого пункта своя причина:

- **F27** SaaS multi-tenant (продавать доступ другим владельцам каналов) —
  отдельный продукт поверх ядра, а не фича; тянет за собой изоляцию данных,
  биллинг и поддержку чужих пользователей.
- **F39** Кросспостинг на VK/Instagram — не входило в скоуп, у каждой площадки
  свой API и свои правила модерации.
- **F49** Платный доступ и подписка (Telegram Stars) — записано как **идея**,
  не как задача: нужен платёжный контур и решение по возвратам.
- **F37** Несколько админов веб-панели с ролями — **пропущено намеренно**:
  пользователь один, роли решали бы несуществующую проблему.
- **F40 веб-сверка v2** — сейчас редактор сверяет с источниками + помеченные
  факты по интернету; можно углубить.

Заблокировано снаружи (код готов, ждёт действий владельца):

- **Guardian** и **Engage** не запущены на стенде — нет `GUARDIAN_BOT_TOKEN` и
  `ENGAGE_BOT_TOKEN`. Оба бота надо завести у @BotFather и вписать в `/settings`.

## 10. Инвентаризация: боты и LLM-агенты

### Telegram-идентичности

| # | Кто | Токен/сессия | С кем говорит | Статус |
|---|---|---|---|---|
| 1 | **Репост-бот** | `tg_bot_token` | владелец | ✅ работает |
| 2 | **Guardian** | `guardian_bot_token` | группа (защита) | ✅ код готов, ждёт токен |
| 3 | **Engage** | `engage_bot_token` | участники (квизы, конкурсы, рефералы) | ✅ код готов, ждёт токен |
| — | **Telethon-аккаунт(ы)** | `tg_session_string` + доп. сессии | читает источники | ✅ работает |

**Итого: 3 бота + 1..N юзер-аккаунтов** (ротация сессий F26 — по аккаунту на
группу источников, у каждого свой почасовой лимит).

### LLM-агенты (роли)

Все ходят через ОДИН клиент (`rewriter/client.py`) и одного провайдера
(`openai_base_url`), но это разные роли с разными промптами:

| # | Роль | Промпт | Где живёт | Когда срабатывает |
|---|---|---|---|---|
| 1 | **Журналист** (5 стилей) | `default/news/opinion/instruction/humor` | `rewriter/client.py` | на каждый вариант рерайта |
| 2 | **Редактор-фактчекер** | `editor.txt` | `rewriter/editorial.py` | F40, если редакция вкл |
| 3 | **Журналист-правщик** | `journalist_revise.txt` | `rewriter/editorial.py` | F40, если есть замечания |
| 4 | **Извлекатель ключевых слов** | `keywords.txt` | `enrichment/enricher.py` | F16, добор источников |
| 5 | **Отборщик источников** | `select_sources.txt` | `enrichment/enricher.py` | F16, выбор 2–3 из выдачи |
| 6 | **Сравниватель версий** | `compare_sources.txt` | `enrichment/enricher.py` | F24, если есть RU+EN |
| 7 | **Автор лонгрида** | `article.txt` | `telegraph/article.py` | формат «статья» |
| 8 | **Постановщик обложки** | `cover_prompt.txt` | `covers/dispatcher.py` | F18, подбор/генерация картинки |
| 9 | **Составитель дайджеста** | `digest.txt` | `scheduler/digest.py` | F20, раз в неделю |
| 10 | **Вписыватель рекламы** | `native_ad.txt` | `ads/injector.py` | F21, каждый N-й пост |
| 11 | **Классификатор спама** | (в коде) | `guardian/filters/ai_filter.py` | G09, на сообщение в группе |
| 12 | **Составитель квиза** | `quiz.txt` | `rewriter/quiz.py` | F43, после публикации поста |

**Итого: 12 ролей, все реализованы.**

Роль №12 живёт в `tg_repost`, а не в `engage`, хотя вопрос задаёт Engage: текст
статьи и LLM-клиент есть только у `tg_repost`, и тащить их в другой процесс ради
одного вызова означало бы дублировать половину пайплайна.

Плюс два не-«агентских» вызова того же провайдера: **эмбеддер** (семантический
дедуп F13, `listener.py`) и **генератор картинок** (`covers/openai_compatible.py`).

### Сколько LLM-вызовов стоит ОДИН пост

Практически важно — это прямая цена поста и причина упираться в 402:

| Конфигурация | Вызовов на пост |
|---|---|
| Минимум (только рерайт, редакция выкл) | **1** |
| Типовая (редакция вкл, 1 вариант, 1 язык) | **3** |
| Всё включено (редакция + добор + сравнение + обложка + дедуп) | **~9** |
| + квиз (F43, один вызов после публикации) | **~10** |

Рерайт-часть умножается на «вариантов × языков»: 3 варианта на 2 языка при
включённой редакции — это уже 18 вызовов только на текст. Отсюда правило:
`rewrite_variant_count` и `editorial_max_rounds` — самые дорогие ручки в системе.
