# Self-hosted автоматизация Telegram — репост-бот + модерация Guardian + геймификация Engage

**Автоматизированный Telegram-бот для репоста с рерайтом через двух ИИ-агентов: парсинг → рерайт и фактчек → модерация → публикация — плюс AI-модератор группы (Guardian) и бот вовлечения аудитории (Engage).**

## Зачем это

Владелец Telegram-канала обычно выбирает между двумя плохими вариантами:
руками пересказывать чужие посты каждый день, либо тупо форвардить с риском
жалоб на копипаст и потери аудитории. Этот проект автоматизирует весь путь
поста от источника до публикации — но интересна тут не автоматизация, а
**редакционное качество**: агент-журналист пишет черновик, агент-редактор
сверяет его с источниками, спорные факты проверяются по интернету, журналист
переписывает. И весь этот спор вы видите живьём в Telegram-чате.

Вокруг пайплайна работают ещё два бота. **Guardian** охраняет группу от
спама, ботов и рейдов, чтобы аудиторию, которую растит первый бот, не
захлестнуло спамом. **Engage** превращает читателей в участников —
викторины по самим постам, реферальная программа с настоящей антинакруткой
и конкурсы с проверяемым розыгрышем.

Все три — production-ready: alembic-миграции с первого дня, 1253 теста,
CI с линтером/тайпчекером/security-сканером на каждый пуш, Docker-упаковка
для деплоя на VPS/Proxmox и единая веб-панель управления вместо ковыряния
в `.env` и БД руками.

Этот README — обзор и быстрый старт.

- **Никогда не запускали Docker или просто хотите быстро поднять систему?**
  Начните с **[Wiki](../../wiki)** — пошаговая инструкция для новичков с FAQ
  и решением частых проблем.

Все три процесса живут в одном репозитории, но это **независимые боты** со
своими токенами и своими циклами перезапуска. Репост-бот и Engage делят одну
БД (`tg_repost.db`) — викторины строятся из постов, а рефералы резолвятся по
тем же участникам; у Guardian своя (`guardian.db`) с отдельной
alembic-цепочкой. Падение или редеплой одного не трогает остальных,
управляются все из единой веб-панели.

## Редакция из двух ИИ-агентов (черновик + фактчек)

Большинство «ИИ-рерайтеров» — это синонимайзеры: один вызов модели, один
результат, никто его не проверяет. Здесь работает настоящий редакционный
процесс, потому что опасна не корявая формулировка, а **уверенно
опубликованная неправда**.

```
① журналист  → пишет черновик (персона копирайтера с 20-летним опытом,
                один из 5 стиль-профилей)
② редактор   → сверяет черновик с ИСХОДНЫМ текстом источника, выносит
                вердикт (OK / ПРАВИТЬ) и список фактов, которые не смог
                подтвердить
③ веб-сверка → именно эти факты проверяются по открытому интернету
④ журналист  → переписывает, отрабатывая каждое замечание
```

- **Редактор — не тот же голос, что журналист.** У него свой промпт и
  температура 0.2, намеренно детерминированная. Креативный фактчекер — это
  противоречие в определении.
- **Замечания пишутся по-человечески**: *«тут неправильно, смотри по такой
  ссылке лучше»* — привязанные к конкретному утверждению, а не абстрактный
  балл качества.
- **Число раундов настраивается** (`editorial_max_rounds`), по умолчанию
  один. Каждый раунд стоит вызовов LLM — это одна из двух самых дорогих
  ручек в системе (вторая — количество вариантов).
- **Замечания сохраняются** в варианте поста и показываются в модерации,
  так что видно, *почему* финальный текст отличается от черновика.
- **Стоимость на виду**: минимум — 1 вызов LLM на пост, типовая конфигурация
  (редакция включена) — 3, всё включено — около 10. Умножайте на «варианты ×
  языки» до того, как включите всё сразу.

### Смотреть спор живьём

Оба агента умеют транслировать переписку в выбранный вами Telegram-чат: вы
видите черновик, возражения редактора, результат веб-сверки и финальный
текст — по мере происходящего. Три режима подробности:

| Режим | Что попадает в чат |
|---|---|
| `all` | Каждый шаг — полная прозрачность, шумно |
| `problems` | Только те посты, где редактор реально возражал |
| `summary` | Одна строка на пост: вердикт и число раундов |

Сообщения группируются в тред по посту и шлются беззвучно
(`disable_notification`) — редакционная кухня не будет будить вас в три ночи.

## Репост-бот — функционал

### Сбор и качество контента
- **Чтение без ограничений Bot API** — Telethon на юзер-сессии видит любые
  публичные/доступные каналы, не только те, где бот-администратор.
- **Фильтр по ключевым словам** — стоп-/обязательные слова глобально или на
  канал, применяется до сохранения в очередь.
- **Двухуровневая дедупликация** — быстрый хэш точных повторов + опциональный
  семантический дубль-чек через эмбеддинги (ловит перефразированные копии
  из разных каналов).
- **Стиль-профили рерайта** — новость / мнение / инструкция / юмор, разные
  промпт-шаблоны, привязка per-source или ИИ сам подбирает голос.
- **Добор источников** — Brave Search находит 2-3 релевантных ссылки
  (рус. + англ.) по теме поста, LLM отбирает лучшие, добавляется блок
  «📚 Источники» — рост доверия аудитории и защита от обвинений в фейках.
- **Сравнение версий события** — если русские и англоязычные источники
  расходятся в трактовке, пост честно помечается «⚠️ разные версии события».
- **Авто-обложки** — если у поста нет медиа, генерация через Unsplash API
  (быстро, бесплатно) или локальный ComfyUI (уникальная AI-генерация).

### Публикация и рост
- **Гибкая модерация** — ручное одобрение кнопками в личке / полный
  автопилот / дрип-постинг по временным слотам, любая комбинация.
- **Мультиканальная публикация** — свои цели на каждый источник
  (`Source.target_chat_ids`), не «всё во все группы».
- **Умное расписание** — анализ истории просмотров вычисляет пиковые часы
  аудитории и рекомендует (или автоматически применяет) сдвиг слотов
  публикации.
- **Авто-дайджест** — раз в неделю LLM сам собирает топ-постов в один
  сводный обзор.
- **Нативная реклама** — каждый N-й пост органично встраивает рекламный
  бриф в стиль канала, ротация по брифам.
- **Growth-трекер** — снимки числа подписчиков + счётчики постов по стилям,
  видно динамику роста канала.
- **Атрибуция подписчиков — какая реклама реально окупилась.** Каждой
  инвайт-ссылке можно задать подпись и стоимость. Telegram сам сообщает, по
  какой ссылке пришёл участник, поэтому панель показывает вступления, уходы,
  удержание на 7 и 30 дней и **цену за того, кто ОСТАЛСЯ** — а не за клик.
  Реклама, приведшая 100 человек, которые за неделю разбежались, честно
  показывается как провал.
- **Авто-реакция на негатив** — считает 👎/💩/😡-реакции, уведомляет
  владельца и опционально удаляет пост при превышении порога (с защитой от
  скоординированного бригадинга — лимит авто-удалений в час).

### Надёжность и масштаб
- **Антибан-механики** — джиттер между запросами, почасовые лимиты чтения —
  снижают риск ограничений юзер-сессии Telethon.
- **Ротация нескольких Telethon-сессий** — балансировка чтения источников
  между аккаунтами при росте числа каналов, отдельный rate-limiter на
  каждую сессию.
- **Статус-машина постов** — чёткие переходы `new → filtered_out |
  duplicate → rewriting → rewritten → pending_approval → approved |
  rejected → posted | failed`, каждый переход логируется.
- **Retry с экспоненциальной задержкой** на все сетевые вызовы (Telegram,
  LLM, поиск).
- **Единый прокси-раздел (MTProto / SOCKS5 / HTTP)** — включаешь тип и
  галочками выбираешь трафик (Telegram, рерайт, картинки); см.
  [«Прокси»](#прокси-mtproto--socks5--http) ниже — **и обязательно прочитайте про ограничение
  fake-TLS перед тем как настраивать.**

## Guardian — AI-модератор группы (капча, антиспам, антирейд)

Отдельный бот на `aiogram`, задача — не проверять контент, а **защитить
живых людей в группе** от спама, ботов и токсиков, пока растёт аудитория.

### Верификация новых участников
- Мут сразу при входе → капча (математика / кнопка «я не робот» /
  тематический вопрос про канал) → снятие ограничений при верном ответе.
- Не ответил за N минут → автокик.
- Гонка «кто первый ответил» и путаница «кто на самом деле новый участник,
  а кто его пригласил» закрыты явной адресацией по `user_id`, а не через
  FSM-контекст aiogram (см. находку в истории коммитов — реальный
  security-баг, который нашли и закрыли).
- **Анализ профиля** — нет username/фото, подозрительное био, свежий
  аккаунт → усиленная капча для рискованных профилей (без авто-бана только
  за профиль — это было бы слишком агрессивно).

### Спам-фильтр — три режима на выбор
| Режим | Как работает | Когда использовать |
|---|---|---|
| `keywords` | Стоп-слова с нормализацией против обхода (омоглифы, zero-width символы, разделители) | Ноль стоимости, для маленьких/тихих групп |
| `ai` | Каждое сообщение — классификатор через OpenAI-совместимое API, JSON-ответ с confidence | Максимальное качество, но токены на каждое сообщение |
| `hybrid` | Эвристики (цены, «пиши в лс», zero-width, форварды, новый аккаунт) отбирают ~20% подозрительных → только они идут в AI | **Рекомендуемый режим** — качество AI по цене keywords |

AI-классификатор **fail-open**: любая ошибка, таймаут или невалидный JSON
трактуется как «пропустить», а не «удалить» — при неуверенности бот никогда
не режет легитимное сообщение.

### Модерация и защита
- **Whitelist-фильтр ссылок**, включая скрытые за текстом (`text_link`).
- **Антифлуд** — лимит сообщений за окно + детект дублей подряд.
- **Система варнов** с эскалацией по наивысшему достигнутому порогу (мут →
  кик → бан), TTL-автосброс варнов по расписанию.
- **Антирейд** — всплеск вступлений замораживает права всего чата
  (с сохранением прежних прав, не дефолтных), кнопки ручной/авто
  разморозки при затишье.
- **Тихие часы** — расписание авто-переключения между строгим (варн за
  любое нарушение) и мягким (только логирование ссылок) режимом.
- **Автодоверие** — участники без нарушений N дней автоматически обходят
  фильтры, снижая AI-нагрузку на активную, уже проверенную аудиторию.
- **Гигиена служебных сообщений** — автоудаление мусора «X вступил в
  группу» / «Y закрепил сообщение», ночной режим, приглушающий собственные
  ответы бота в тихие часы, и периодическое напоминание правил.
- **Автоответы по ключевым словам** — правила для повторяющихся вопросов
  («когда стрим?», «где правила?») со срабатыванием строго по границам слова
  («кот» не сработает на «котлету») и кулдауном на правило, чтобы бота
  нельзя было превратить во флуд-машину.
- **Лог-канал** — каждое действие модерации, ручное и автоматическое,
  пишется в приватный канал с inline-кнопками для быстрой реакции админа.
- **SOCKS5/HTTP-прокси для Bot API** — см. [«Прокси»](#прокси-mtproto--socks5--http) ниже.
- **21 команда администратора** — `/warn /mute /unmute /ban /unban /kick
  /check /addword /delword /listwords /trust /untrust /addomain /deldomain
  /listdomains /setmode /setcaptcha /setwarn /setmutime /mode /stats
  /growth` — весь конфиг меняется на лету, без перезапуска бота.

## Engage — читатели становятся участниками (викторины, рефералы, конкурсы)

Третий бот, тоже на `aiogram`. Guardian не пускает плохих, Engage даёт
хорошим повод остаться. Каждая механика здесь построена вокруг одного
правила: **награду должно быть трудно накрутить**, иначе таблица лидеров
превращается в список тех, кто завёл больше фейков.

### Викторины по вашим же постам

После публикации LLM составляет вопрос с вариантами ответа по этому посту.
Вопрос выходит **нативным quiz-опросом Telegram** после паузы на прочтение —
Telegram сам проверяет ответ, показывает верный вариант с пояснением и не
даёт переголосовать.

- **Ноль вызовов LLM на проверку** ответов и ноль споров «я это и имел в
  виду» — судья тут платформа.
- Вопрос строится по **уже проверенному материалу** (текст статьи извлечён,
  редактор его сверил), поэтому викторина не может выдумать то, чего в посте
  не было.
- Очки: **10** за верный ответ плюс бонус за серию **5** (максимум **25**).
  Серии считаются по *календарным датам* — их не накрутить, ответив дважды
  за вечер.
- `/me` — очки, точность и серия; `/top` — таблица лидеров.

### Реферальная программа с настоящей антинакруткой

У каждого участника своя пригласительная ссылка (`/invite`). Реферал
засчитывается, только когда приглашённый **вступил, написал хотя бы одно
сообщение и прожил в группе N дней**.

- **Сам себя пригласить нельзя**, а уже засчитанного участника нельзя
  «перебить»: кто привёл первым, тот и привёл — гонки за чужого реферала не
  возникает.
- Условие «написал сообщение» — ключевое: одноразовый мультиаккаунт вступит
  ради награды, но разговаривать не станет.
- **50 очков** за подтверждённого реферала — намеренно дороже ответа на
  вопрос: привести живого человека полезнее, чем ответить на один вопрос.

### Конкурсы, в честности которых можно убедиться

Беда розыгрышей в каналах — никто не может проверить, что победитель не друг
владельца. Поэтому розыгрыш здесь **воспроизводимый**:

1. Случайный seed генерируется **в момент создания конкурса** — до того, как
   появился хоть один участник, — и публикуется заранее.
2. Участники сортируются по user_id (устойчивый порядок, который никто не
   контролирует).
3. Победители выбираются от этого seed, а после публикуется протокол с
   seed, названием алгоритма и полным списком участников.

Любой может повторить розыгрыш и получить тех же победителей.
Непредсказуемость обеспечивает seed, сгенерированный через `secrets`, а сам
розыгрыш детерминирован намеренно: криптослучайный жребий был бы
непроверяемым — то есть терял бы весь смысл.

### И по мелочи — то, чем группа живёт

- **Онбординг в личке** — новичок получает личное приветствие с разбором
  правил и того, о чём канал, вместо простыни в закрепе, которую никто не
  читает.
- **Предложка (UGC)** — `/suggest` позволяет участникам присылать вам посты;
  они попадают в ту же очередь модерации, что и всё остальное, а `/cancel`
  прерывает отправку.
- Всё **выключено по умолчанию** (`QUIZ_ENABLED`, `REFERRALS_ENABLED`,
  `CONTESTS_ENABLED`, `SUGGESTIONS_ENABLED`, `ONBOARDING_ENABLED`) —
  включайте только те механики, которые вам действительно нужны.

## Веб-админка

Единая FastAPI-панель на все три бота, встроена в тот же процесс, что и
`main.py` (не отдельный сервис) — настройки применяются живо, логи
стримятся в браузер без межпроцессной синхронизации.

- **`/setup`** — визард первого запуска: пароль администратора + Telegram
  вход прямо в браузере (телефон → код → 2FA), без ковыряния в терминале.
- **`/`** дашборд — воронка постов по статусам, токены рерайта за сегодня,
  доля ошибок за 24ч, статус компонентов (listener/бот/планировщик).
- **`/sources` `/targets` `/moderation` `/ads` `/stats`** — полный CRUD
  зеркалит CLI и Telegram-бота на одной и той же бизнес-логике (не две
  версии кода, которые могут разойтись).
- **`/settings`** — ~25 настроек по фиче-группам, применяются сразу live;
  поля с пометкой `resync` автоматически пересобирают джобы планировщика.
- **`/secrets`** — write-only форма: значение шифруется (`Fernet`) и
  никогда не возвращается в браузер, только маска `••••a1b2`.
- **`/components`** — живой рестарт Telethon-листенера/бота без
  перезапуска процесса после смены токена/сессии.
- **`/guardian*`** — управление Guardian из той же панели: режим
  спам-фильтра, пороги варнов, стоп-слова, whitelist доменов, доверенные
  пользователи — без единой Telegram-команды.
- **`/audit`** — журнал всех действий из админки (кто, что, когда).
- **`/logs`** — живые логи процесса через Server-Sent Events, без
  WebSocket-инфраструктуры.

Доступ — только localhost/VPN по дизайну (без обязательного TLS), сессии
с idle- и абсолютным таймаутом, rate-limit на `/login`, Argon2id для
пароля.

## Прокси (MTProto / SOCKS5 / HTTP)

Единый раздел «Прокси» на `/settings`. Включаешь один или несколько
**типов**, вписываешь адрес каждого (и, если нужно, логин + пароль), затем
галочками отмечаешь, какой трафик через него гнать. Три типа и три галочки
применения:

- **Типы:** **MTProto** (специфичный для Telegram fake-TLS-прокси, только
  для Telethon, вместо логина/пароля — *секрет*), **SOCKS5** и **HTTP(S)**
  (обычные туннели — годятся для Telethon, Bot API и нейросетей).
- **Галочки применения:** *Telegram* (чтение Telethon + Bot API обоих ботов),
  *нейросеть рерайта*, *картиночная нейросеть*.

| Что | Секрет? | Примечание |
|---|---|---|
| Адрес (`host:port`), логин | обычные, редактируются на `/settings` | никогда не прячутся — без пароля/секрета всё равно бесполезны |
| Пароль / секрет MTProto | write-only секрет | замаскирован; кнопка **«показать» — в один клик** (ты уже залогинен) |
| Галочки применения | обычные чекбоксы | по трафику: Telegram / рерайт / картинки |

Приоритет при нескольких включённых типах: для **Telegram** — SOCKS5 → HTTP →
MTProto; для **нейросетей** — HTTP → SOCKS5 (MTProto только для Telegram).
Все типы выключены = прямое соединение (по умолчанию).

Прокси Bot API у Guardian — **отдельный** (только `.env`,
`GUARDIAN_BOT_API_PROXY_URL`): Guardian — другой процесс, строится один раз
при старте, смена требует `docker compose restart guardian`.

> ⚠️ **Прочитайте это перед настройкой MTProto-прокси.** Встроенная
> поддержка MTProto-прокси в Telethon **не умеет** режим fake-TLS (секреты
> с префиксом `ee`) — известное ограничение самой библиотеки, а не то, что
> можно починить на стороне этого проекта. Большинство
> современных публичных MTProto-прокси работают именно в fake-TLS. Если ваш
> секрет начинается с `ee` — Telethon либо зависнет, либо упадёт с ошибкой
> рассинхронизации шифрования. **Проще всего взять SOCKS5 или HTTP(S)-прокси**
> — у обычных туннелей нет ограничения fake-TLS. Либо взять классический
> (обычный hex / `dd`) секрет с того же прокси. **Подробности, реальные
> тексты ошибок и алгоритм — в [Wiki, раздел «Прокси»](../../wiki/Proxy-Guide-RU).**

## Стек

| Слой | Технология | Почему |
|---|---|---|
| Чтение каналов | **Telethon** (юзер-сессия) | Bot API не даёт читать чужие каналы без прав администратора |
| Публикация/модерация | **python-telegram-bot** (репост) · **aiogram 3.x** (Guardian) | aiogram — FSM из коробки для многошаговой капчи |
| Рерайт/классификация | **OpenAI SDK**, любой совместимый `base_url` | GPT-4o-mini, Claude через прокси, локальная llama.cpp/Ollama — без смены кода |
| БД | **SQLite + SQLAlchemy + Alembic** | Простота, один файл, лёгкий бэкап; путь на Postgres открыт с первого дня |
| Планировщик | **APScheduler** | Cron-джобы внутри процесса, без Celery/Redis для одного оператора |
| Веб-админка | **FastAPI + Jinja2 + Starlette Sessions** | Встроена в общий event loop, live-reload настроек без пересборки фронта |
| Секреты | **Fernet (cryptography)** + Argon2id | Симметричное шифрование at rest, write-only UI |
| CI | **GitHub Actions**: ruff · mypy · pytest · bandit · pip-audit | Каждый пуш проверяется линтером, тайпчекером и двумя security-сканерами |
| Деплой | **Docker + docker-compose** | Два сервиса на общем образе, разные entrypoint, изолированные volume |

## Быстрый старт (без Docker)

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# bash/zsh:
# source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env   # заполнить секреты (или оставить пустым — настроишь в /setup)

alembic upgrade head            # схема репост-бота
alembic -c alembic_guardian.ini upgrade head   # схема Guardian (если запускаешь и его)

python -m tg_repost.main
```

Открой `http://127.0.0.1:8000/setup` — веб-визард поднимется даже без единой
заполненной переменной в `.env`. Дальше всё управляется из браузера.

Для Telethon нужна session string:
```bash
python -m tg_repost.tools.gen_session
```
(Либо не запускать это вообще, а нажать кнопку **«Войти через Telegram»**
в веб-визарде — она делает весь флоу телефон/код/2FA прямо в браузере.)

Guardian запускается отдельным процессом:
```bash
python -m guardian.bot
```
Бота нужно добавить в защищаемую группу **администратором** с правами:
удаление сообщений, бан/кик участников, ограничение прав (мут), управление
приглашениями (для антирейда).

## Docker-деплой

Это рекомендуемый способ запуска проекта. Если вы никогда не работали с
Docker — читайте дальше, но для максимально подробного, беспроблемного
пошагового гайда со скриншотами типичных ошибок используйте
**[Wiki: Installation-RU](../../wiki/Installation-RU)** вместо этой
сокращённой версии.

### 1. Установить Docker

**Debian/Ubuntu:**
```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# Выйдите и зайдите заново (или выполните `newgrp docker`) — членство в
# группе не применится к текущей сессии терминала, пока вы этого не сделаете.
```

Проверка:
```bash
docker compose version
```
Если ругается что-то вроде `unknown command "compose"` — значит стоит
старый standalone `docker-compose` (или вообще ничего), а не плагин
Compose V2, на который рассчитаны команды в этом проекте. Установить:
```bash
sudo apt update && sudo apt install docker-compose-plugin
```

**Windows/macOS:** поставьте [Docker Desktop](https://www.docker.com/products/docker-desktop/) — Compose V2 уже встроен.

### 2. Склонировать репозиторий

```bash
git clone https://github.com/RakinSV/Telegram-admin-app-project.git
cd Telegram-admin-app-project
```

### 3. Создать `.env` — **до** первого `docker compose up`

```bash
cp .env.example .env
```

Этот шаг не опционален, и порядок важен: если `.env` ещё не существует,
bind mount Docker'а (`./.env:/app/.env` в `docker-compose.yml`) создаст на
его месте **директорию**, а не примонтирует файл — контейнер упадёт с
непонятной ошибкой. Заполнять руками ничего не обязательно — оставьте все
секреты пустыми, зададите их позже через веб-визард `/setup`. Единственное,
что стоит сделать сейчас — открыть `.env` и пробежаться по комментариям,
чтобы понимать, что там вообще есть.

### 4. Запустить

```bash
docker compose up -d --build
```

Первый билд займёт пару минут (тянутся зависимости). Два сервиса на одном
образе — `tg_repost` (веб-админка + репост-пайплайн, публикуется на
`127.0.0.1:8000`) и `guardian` (модерация группы) — с разными entrypoint,
независимым рестартом (`unless-stopped`), общим `.env` и раздельными volume
для БД/логов/медиа.

Проверить, что всё поднялось:
```bash
docker compose ps
docker compose logs -f tg_repost
```

### 5. Открыть админку

Порт публикуется как `127.0.0.1:8000` — **только loopback хоста**, это
осознанное решение, тот же периметр localhost/VPN-only, что и без Docker.
Если вы на той же машине — открывайте `http://127.0.0.1:8000/setup` в
браузере. Если деплоите на **удалённый сервер** — есть два варианта, оба
подробно разобраны с точными командами в
**[Wiki](../../wiki/Installation-RU#шаг-6--открыть-админку)**:
- SSH-туннель с ноутбука (`ssh -L 8000:127.0.0.1:8000 user@server`), либо
- `docker-compose.override.yml`, публикующий порт на VPN/LAN-интерфейс
  вместо `127.0.0.1` (никогда не публикуйте эту панель напрямую на
  публичный IP без reverse-proxy и TLS перед ней).

При первом запуске в логи печатается одноразовый токен для `/setup` —
достать его:
```bash
docker compose logs tg_repost | grep -i token
```

Дальше: создаёте пароль администратора, затем кнопкой **«Войти через
Telegram»** на странице `/secrets` подключаете Telethon-аккаунт (телефон →
код → 2FA, прямо в браузере, без терминала).

### 6. Обновление

```bash
git pull
docker compose up -d --build
```
`.env` и обе базы данных (в `./data/`) не трогаются — они живут вне
образа, в примонтированных volume.

### Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `unknown command "compose"` | Не установлен плагин Compose V2 | `sudo apt install docker-compose-plugin` |
| `permission denied ... docker.sock` | Членство в группе после `usermod -aG docker` ещё не применилось | Перелогиньтесь, или `newgrp docker` |
| `.env` создался как директория | `docker compose up` запустили до того, как `.env` появился | `docker compose down`, `rmdir .env` (она пустая), `cp .env.example .env`, повторить |
| `/guardian*` падает 500 "no such table" | Рассинхронизация `GUARDIAN_DATABASE_URL` между сервисами, либо устаревший образ до фикса | `docker compose up -d --build`, чтобы пересобрать оба сервиса из текущего `docker-compose.yml` |
| Вход в Telethon зависает или падает с непонятной ошибкой | MTProto-прокси в режиме fake-TLS — не поддерживается, см. [«Прокси»](#прокси-mtproto--socks5--http) выше | Читайте [Wiki: Proxy-Guide-RU](../../wiki/Proxy-Guide-RU) |

Больше сценариев с реальными текстами ошибок — в
**[Wiki: FAQ-RU](../../wiki/FAQ-RU)**.

([`.github/workflows/ci.yml`](.github/workflows/ci.yml)). Каждая фича в
этом репозитории прошла минимум один цикл ревью code-reviewer +
security-auditor агентами — реальные находки (от path traversal до гонки
состояний в капче и обхода авторизации в антирейде) исправлены и закрыты
регрессионными тестами, не просто описаны в issue.

## Бэкап

```bash
python -m tg_repost.tools.backup            # хранит последние 14 бэкапов
0 3 * * * cd /path/to/repo && python -m tg_repost.tools.backup   # cron
```
Архивирует `.env` + обе SQLite БД + `logs/` в один zip — без `.env`
зашифрованные секреты в БД невосстановимы, поэтому бэкапятся вместе.
Права файла архива ограничены `0600`; не синкать `backups/` в облако без
отдельного шифрования (`age`/GPG).

## Структура проекта

```
tg_repost/              # репост-бот
  webui/                 # веб-админка на все три бота (FastAPI + Jinja2)
  telegram/               # Telethon listener, publisher, moderation bot, newsroom
  rewriter/                # LLM-клиент: редакция, стили, викторины, эмбеддинги
  dedup/                    # хэш + семантический дубль-чек
  enrichment/                # Brave Search добор источников + извлечение статей
  covers/                     # Unsplash / ComfyUI / OpenAI-совместимые обложки
  ads/                         # нативная реклама
  scheduler/                    # APScheduler джобы: постинг, статистика, дайджест, рост
  db/                            # ORM + alembic-миграции (27)
  tools/                          # gen_session, check_telethon, backup

guardian/                # AI-модератор группы (отдельный бот, своя БД)
  handlers/                # join (капча), messages, admin, гигиена, автоответчик
  filters/                   # keyword / ai / heuristics / link / flood
  services/                   # warn_system, captcha, raid_detector, profile_analyzer
  db/                           # своя ORM + alembic-цепочка

engage/                  # бот вовлечения аудитории (делит БД с tg_repost)
  handlers/                # quiz, referral, contest, suggest, start (deep-links)

tests/                   # 1253 теста — pytest + pytest-asyncio
.github/workflows/       # CI: ruff, mypy, pytest, bandit, pip-audit
```

У Engage **намеренно нет своей БД**: викторины строятся из постов,
реферальные ссылки — это те же инвайт-ссылки, что создаёт репост-бот, а
приглашённые попадают в ту же таблицу атрибуции. Отдельная база означала бы
синхронизацию всех трёх через границы процессов.
